# 13F 컨센서스 레이더 — 실데이터·실전 투자용 설계

- 작성일: 2026-09-23
- 상태: 승인됨(대화에서 설계 승인) → 구현 계획 작성 전 검토
- 위치 메모: 기본 위치(`docs/superpowers/specs/`)는 GitHub Pages가 `docs/`를 공개하므로 쓰지 않고 `design/`에 둔다.

## 1. 목적과 성공 기준

버핏 등 앵커 투자자가 매수했고 복수의 거물급 투자자가 같은 분기에 함께 투자한 미국 주식을 SEC EDGAR 13F 원자료에서 골라,
**지금 가격에 샀을 때의 기대수익(1주·1달·1년·3년·5년)** 과 함께 매일 갱신되는 웹페이지로 보여준다.

성공 기준
1. 페이지의 모든 종목·수치가 실제 SEC 공시와 실제 주가에서 나온다(예시 데이터 없음).
2. 매일 08:00 KST에 GitHub Actions가 자동 갱신하고, PC가 꺼져 있어도 폰에서 GitHub Pages URL로 볼 수 있다.
3. 파싱 결과가 공시 원문 합계와 맞는지 자동 점검되고, 티커 오매핑은 가격 대조로 걸러진다.
4. 각 시그널 종목에 대해 "지금 사면" 기대수익·범위·상승확률·S&P500 대비, 추정 매입가 대비 현재가, 원화 가격,
   애널리스트 목표가(참고), 전략 트랙레코드, 최근 90일 수시 공시(Form 4·13D·13G)가 표시된다.
5. 편향과 한계(13F 지연, 생존편향 등)가 페이지에 숨김없이 표시된다.

## 2. 범위

포함: 데이터 정확도 보강, 실제 첫 전체 수집, 기대수익 개선, 추정 매입가, 원화·애널리스트 목표가, 전략 트랙레코드,
정렬·리서치 링크, Form 4·13D·13G 수시 공시, 모듈 분리와 테스트, GitHub 배포 자동화, README 갱신.

제외: 증권사 주문 연동, 알림(메일·메신저), 로그인/개인화, 옵션(Put/Call) 포지션 분석, 비미국 증권.

## 3. 아키텍처

정적 사이트 파이프라인을 유지한다. 서버·DB 없음.

```
GitHub Actions (매일 23:00 UTC = 08:00 KST)
  └─ python build.py
       ├─ radar/sec.py       SEC 요청(초당 8회 토큰버킷, 스레드 6개, 재시도)
       ├─ radar/edgar.py     13F 목록·파싱·캐시·수정신고 병합·다중 CIK 병합·13F-NT 추적
       ├─ radar/classify.py  직전 분기 대비 신규/추가/유지/축소/매도, 주식분할 판정
       ├─ radar/tickers.py   CUSIP→티커(OpenFIGI, 캐시)
       ├─ radar/prices.py    yfinance 주가(수정/비수정 종가·거래량·분할), 환율, 애널리스트 목표가
       ├─ radar/metrics.py   표시 종목의 현재가·경과일·변동성·52주·추정 매입가·가격 검증
       ├─ radar/backtest.py  과거 시그널 이벤트, 청크 단위 선행수익률, 가격 검증
       ├─ radar/filings.py   Form 4·13D·13G 최근 90일 파싱
       └─ 출력: docs/data.json, docs/index.html(template.html + 데이터 내장)
  └─ data/ 변경분 커밋 → docs/를 Pages 아티팩트로 배포(docs/는 커밋하지 않음 — 매일 수 MB 커밋으로 저장소가 비대해지는 것 방지)
```

- `build.py`는 순서만 조율하는 얇은 진입점이 된다. 각 모듈은 하나의 책임과 좁은 함수 인터페이스를 갖고, 네트워크 호출은
  `SecClient`·가격 다운로드 함수로만 들어가 테스트에서 가짜로 바꿀 수 있다.
- 화면은 계속 단일 HTML 파일(데이터 내장, 로컬 파일로도 열림). 계산 로직은 `/*CORE-BEGIN*/ … /*CORE-END*/` 구간의
  순수 함수로 모아 Node 테스트에서 떼어 실행한다.

## 4. 데이터 파이프라인 상세

### 4.1 투자자 설정 (`investors.json`)
```json
{"id":"ackman","label":"빌 애크먼","fund":"Pershing Square","tier":"A",
 "ciks":["0001336528","0002026053"],"expect":["PERSHING"]}
```
- `ciks`(여러 개 가능)와 `expect`(EDGAR 등록명에 포함될 문자열 목록). 기존 `cik`/`expect` 단일 문자열도 읽는다.
- 이번에 바꿀 항목: 애크먼 `+0002026053`(Pershing Square Inc.), 아인혼 `+0001489933`(DME Capital Management, expect에 "DME" 추가).
  버리(Scion)는 목록에 두되 자동으로 `inactive` 판정된다.

### 4.2 SEC 요청 (`radar/sec.py`)
- `SecClient(ua, max_rps=8, workers=6)`: `get(url)->bytes`, `get_json(url)`, `map(fn, items)`(스레드 풀).
- 전역 토큰버킷으로 초당 8회 이하(SEC 한도 10회). 429·403·5xx는 지수 백오프 재시도(최대 5회), 404는 즉시 None.
- User-Agent: 환경변수 `SEC_USER_AGENT`(예: `13F-Consensus drchulfe@gmail.com`). `@`가 없으면 즉시 종료.

### 4.3 13F 수집·파싱·캐시 (`radar/edgar.py`)
- 제출 목록: CIK별 `submissions/CIK##########.json` + 과거 페이지(`filingTo >= 2013-06-30`). 13F-HR, 13F-HR/A, 13F-NT, 13F-NT/A.
- 파일 찾기: 접수번호 `index.json`에서 `primary_doc.xml`(표지)과 정보표 XML을 고른다. 정보표 = 표지를 뺀 XML 중
  이름에 info/table이 있으면 그것, 없으면 **크기가 가장 큰 XML**(실제 예: 버크셔 `56757.xml`).
- 표지 파싱: 보고기간, 수정 유형(RESTATEMENT/NEW HOLDINGS), 보고 유형, `tableValueTotal`, `tableEntryTotal`,
  13F-NT의 `otherManagersInfo`(CIK·이름).
- 정보표 파싱: 행마다 종목명·클래스·CUSIP·value(보고 단위 그대로)·주식수·SH/PRN·Put/Call.
- **단위 판정**: 옵션·PRN을 뺀 행의 `value/주식수` 중앙값이 1.0 미만이면 천달러 단위, 아니면 달러 단위.
  유효 행이 3개 미만이면 제출일 규칙(2023-01-03 이전 = 천달러)으로 대체.
- **합계 점검**: 전체 행 value 합과 `tableValueTotal`(같은 단위) 차이 1% 초과, 행 수와 `tableEntryTotal` 불일치를 기록.
- 캐시 `data/cache/{acc}.json` (`"v": 2`): 메타 + CUSIP별 합산 보유(보고 단위 value, 주식수) + 점검값.
  단위 변환은 읽을 때 수행하므로 판정 규칙이 바뀌어도 재다운로드가 필요 없다. v1 캐시는 무시하고 다시 받는다.

### 4.4 분기 확정·병합
- 한 CIK의 같은 분기 공시를 제출일 순으로 적용: 원본(13F-HR) 또는 RESTATEMENT는 교체, NEW HOLDINGS는 합산.
- **공시일 도장**: 보유 행마다 공개된 날짜 `f`를 단다. RESTATEMENT로 교체할 때 이전과 주식수가 같은 행은 기존 `f`를 유지하고,
  새로 생기거나 바뀐 행만 수정신고일을 쓴다(몇 년 뒤 재작성으로 진입일이 밀리는 오류 방지).
- **다중 CIK 병합**: 같은 분기에 여러 CIK가 보고하면 13F 평가액 합계가 가장 큰 CIK를 쓴다(주 보고자 선택).
  사용한 CIK는 `filed[].cik`에 기록.
- **13F-NT 추적**: CIK의 가장 최근 13F류 공시가 13F-NT면 표지의 다른 매니저를 조회해 등록명이 `expect`와 맞으면
  자동으로 CIK 목록에 추가(로그와 화면에 "자동 추적" 표시), 안 맞으면 "13F-NT: 보고 주체 ○○(CIK) — 추가 검토" 메모.
- **활동 상태**: 제출기한(분기말+45일, 주말이면 다음 평일)이 지난 가장 최근 분기를 Q라 할 때, 투자자의 최신 분기가
  Q의 직전 분기보다 오래됐으면 `inactive`.

### 4.5 변화 분류 (`radar/classify.py`)
- 기존 규칙 유지: 정확히 직전 분기와 비교해 new/add/hold/reduce/sold, 직전 분기가 없으면 first(매수로 세지 않음).
- 주식분할 판정 유지(보유 지속자의 주식수 비율이 모두 같은 정수배).
- 화면용 분기(최근 2개)에는 **매수(new/add)가 1명 이상인 종목만** 내보낸다(데이터 크기 절감). 해당 종목의 모든 투자자 행은 유지.

### 4.6 티커 매핑 (`radar/tickers.py`)
- OpenFIGI `v3/mapping`(idType=ID_CUSIP, exchCode=US). 키 있으면 100건/요청, 없으면 10건/요청·요청 간 2.6초.
- 결과 없음은 `""`로 캐시, 네트워크 오류는 캐시하지 않아 다음 실행에서 재시도. 캐시 `data/cusip_map.json`.

### 4.7 주가와 검증 (`radar/prices.py`, `radar/metrics.py`)
- 다운로드: `yf.download(auto_adjust=False, actions=True, group_by="ticker")`를 100개씩. 티커별로
  수정종가(Adj Close, 배당·분할 반영) · 종가(Close, 분할만 반영) · 거래량 · 분할 비율을 쓴다.
  청크를 처리한 뒤 버려 메모리를 제한한다(과거 전체 수천 종목 대비).
- **가격 검증**: 분기말 p의 13F 내재가격 = Σ평가액/Σ주식수(보유 투자자 합). Yahoo 원시가격 = p 이전 마지막 거래일 Close ×
  (p 이후 모든 분할 비율의 곱). 비율이 0.8~1.25이면 통과. 실패하면 백테스트 표본에서 빼고(`mismatch`로 집계),
  화면에서는 가격 기반 수치를 숨기고 "티커 확인 필요" 표시.
- 표시 종목 지표(`px`): 현재가(전일 종가)·기준일, 시그널 진입 후 경과 거래일 `el`, 진입 후 수익률(수정종가),
  최근 1년 연환산 변동성, 52주 고가·저가, 검증 결과 `ok`, **추정 매입가**(해당 분기 거래일의 종가×거래량 가중평균 VWAP,
  분기 저가·고가, 현재가의 VWAP 대비 프리미엄), 원화 가격.
- 환율: `KRW=X` 최근 종가.
- 애널리스트 목표가: `yf.Ticker(t).info`의 targetMeanPrice/targetMedianPrice/numberOfAnalystOpinions/recommendationKey.
  기본 조건 후보(매수 2명+ 또는 앵커 매수+보유 2명+)만, 실행당 최대 250개, `data/analyst.json`에 7일 캐시. 실패하면 생략.

### 4.8 백테스트 (`radar/backtest.py`)
- 이벤트: 2013년~ 모든 분기에서 분할이 아닌 종목 중 **매수자 1명 이상이고 보유자(매수 포함) 2명 이상**.
  (기존보다 넓힘 — 화면의 모든 필터 조합이 같은 표본 풀에서 계산되도록.)
- 진입일 e = 매도 아닌 행들의 공시일 중 가장 늦은 날. 매수가 = e **다음** 거래일 수정종가.
- 오프셋 = {k+h | k∈{0,21,63,126}, h∈{5,21,252,756,1260}} ∪ {0,21,63,126} 거래일의 누적수익률 R, 같은 구간 SPY 수익률 S.
- 가격 검증 통과 이벤트만 사용. 통계: 전체/가격없음/검증실패/사용 건수.
- 저장 형식(크기 절감): `P`(분기 목록)·`I`(투자자 id 목록)를 두고 `ev = [P인덱스, 티커, [투자자인덱스×2+신규여부], 보유자수, R(퍼밀 정수, 뒤쪽 null 제거), spy인덱스]`, `spy = [S(퍼밀), …]`(진입일별 1개). 화면에서 풀어서 사용.
- 전체 재계산: 캐시 없음, 일요일(UTC), 또는 `FULL_BACKTEST=1`. 그 외 날은 캐시 사용.

### 4.9 수시 공시 (`radar/filings.py`)
- 추적 투자자 CIK의 제출 목록(13F 수집 때 받은 것 재사용)에서 최근 90일의 `4`, `4/A`, `SCHEDULE 13D(/A)`, `SCHEDULE 13G(/A)`.
  (2024-12 이후 13D/G는 XML. 옛 `SC 13D/G` 텍스트 형식은 건너뜀.)
- 원문 XML 경로 = `primaryDocument`에서 `xsl…/` 접두어를 뗀 파일(예: `ownership.xml`, `primary_doc.xml`).
- Form 4: 발행사 CIK·이름·티커, 거래코드 P(장내매수)·S(장내매도)의 주식수·가격·거래 후 보유. 한 공시의 여러 거래는 합산
  (가중평균가). 티커가 "LEN, LEN.B"처럼 여럿이면 증권명에 Class B가 있으면 `.B`, 아니면 첫 티커.
- 13D/13G: 발행사 CIK·이름·CUSIP, 보고자별 보유주식수·지분율 중 최대값, 수정 번호, 사건일. 네임스페이스를 떼고
  `issuerCik`/`issuerCIK` 대소문자를 모두 받는다.
- **발행사 CIK가 투자자 자신의 CIK면 제외**(예: 버핏이 제출한 버크셔 자사 13D/A).
- 접수번호별 캐시 `data/cache/f_{acc}.json`. 최대 300건 출력.

## 5. 출력 데이터 스키마 (`docs/data.json`, 페이지에 내장)
```
generated_at, price_date, fx:{krw,d}|null,
investors:[{id,label,fund,tier,ciks,edgar_names,status,last_period,notes[]}],
periods:{ "YYYY-MM-DD": {
  filed:[{inv,cik,filed,last_filed,accs,n,aum,has_prev}],
  stocks:[{cusip,name,cls,tk,split,
           actions:[{inv,t,sh,psh,v,w,f}],
           px:{last,d,el,since,vol,hi52,lo52,ok,vwap,qlo,qhi,prem,krw}|null,
           an:{mean,median,n,rec,d}|null}] } },
bt:{built,K,H,O,stats:{total,nopx,mismatch,used},ev:[...],spy:[...]}|null,
filings:[{d,inv,form,kind,tk,name,cusip,sh,px,val,pct,post,td,acc,cik}],   (td = 거래일/사건일)
sanity:{filings,total_mismatch,count_mismatch,validated,unvalidated}
```
목표 크기: 페이지 8MB 이하. 첫 실행 후 실측해 넘으면 표시 분기 종목·이벤트 필드를 더 줄인다.
`docs/data.json`은 로컬 확인용으로만 만들고 커밋하지 않는다.

## 6. 기대수익 정의 ("지금 사면")
- 표본: 선택 분기보다 **이전** 분기의 이벤트 중 현재 필터(앵커·동시 투자 기준·최소 인원·신규만)를 만족하는 것.
  종목의 동시 인원 n(4명 이상은 4)과 같은 인원 표본을 우선 쓰고, 1년 표본이 30건 미만이면 조건 전체 표본을 쓴다.
- 경과 보정: 종목의 경과 거래일 el 이하인 가장 큰 k∈{0,21,63,126}. 이벤트별 x = (1+R[k+h])/(1+R[k]) − 1, SPY도 같게.
- 기간별 통계: 표본 수, 중앙값, 평균(1%·99% 윈저화), 상승확률 P(x>0), SPY 대비 초과수익 중앙값, 경험적 16~84% 구간.
- 3·5년은 연환산 병기: (1+값)^(252/h) − 1.
- 68% 범위: 종목 1년 변동성 σ로 exp(ln(1+중앙값) ± σ√(h/252)) − 1.
- 표시 규칙: 표본 10건 미만은 "–", 30건 미만은 "표본 적음" 표시. 가격 검증 실패 종목은 기대수익 숨김.
- 요약줄 표시값은 중앙값 기본, "평균" 전환 버튼 제공(설정은 브라우저에 저장).

## 7. 전략 트랙레코드 정의 (브라우저 계산)
- 현재 필터를 만족하는 이벤트를 분기(코호트)별로 묶어, 각 코호트의 동일가중 평균 3개월(63거래일) 수익률 r과 SPY 수익률 s.
- 분기 교체 전략 NAV = Π(1+r), SPY NAV = Π(1+s). 이벤트가 없는 분기는 현금(0%)으로 둔다. 63거래일이 안 지난 코호트는 제외.
- 요약: 연환산 수익률(CAGR), 분기 기준 최대낙폭, SPY 초과 분기 비율, 코호트 수. 1년 보유 평균수익률(R[252]) 표도 함께.
- 한계 문구: 진입일이 공시 시즌에 흩어져 있어 근사치, 생존편향, 거래비용·세금 미반영.

## 12. 페이지에 표시할 한계
13F는 분기말 스냅샷(최대 45일 지연)이고 롱 포지션·미국 상장 증권만 보인다. 기대수익은 과거 기저율이며 예측이 아니다.
상장폐지 종목이 빠져 수익률이 위로 치우친다(생존편향). 옛 CUSIP은 현재 티커로 매핑돼 가격 검증으로 거르지만 완벽하지 않다.
거래비용·세금·환율 변동은 반영하지 않는다. 투자 권유가 아니다.

## 13. 결정 기록
- 정적 사이트 유지: 호스팅 무료, 운영 부담 없음, 기존 설계 재사용. 서버형 웹앱은 이득 대비 유지보수가 크다.
- 기대수익은 과거 기저율 + 종목별 참고치: 수익률 예측 모델은 잡음이 커서 과적합 위험이 크다.
- 다중 CIK는 평가액 최대 CIK 선택: 모회사(Pershing)·후속 법인(Greenlight→DME) 모두에서 주 보고자를 고른다.
- 이벤트 표본 확대(매수 1명+·보유 2명+): 화면의 모든 필터 조합을 같은 표본 풀에서 일관되게 계산하기 위함.
