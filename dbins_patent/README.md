## 2. 데이터 수집 (KIPRIS)

1. kipris.or.kr에서 특허·실용신안 → 스마트 검색을 엽니다.
2. 출원인에 `DB손해보험`과 `동부화재해상보험`을 OR로 넣습니다. 2017년 사명 변경 이전 출원을 함께 잡기 위해서입니다.
   - 출원인코드(applicant code)로 검색하면 표기 차이를 피할 수 있습니다. 코드는 검색 결과 상세 화면에서 확인하세요.
3. 출원일은 2016-01-01 ~ 2025-12-31로 지정합니다.
4. 검색 결과를 엑셀로 다운로드합니다. 열 선택이 가능하면 다음을 반드시 포함하세요: 출원번호, 출원일자, 발명의명칭, 요약, IPC, 출원인, 등록번호, 행정처리상태.
5. **추출일을 기록하세요.** `--asof` 인자로 넣어야 합니다.

> **확인 못 함:** KIPRIS 다운로드 파일의 정확한 열 이름은 이 환경에서 접속할 수 없어 검증하지 못했습니다.
> 열 이름이 다르면 스크립트가 실제 열 목록을 출력하고 멈춥니다. 그 이름을 `analyze.py`의 `COLUMN_ALIASES`에 추가하면 됩니다.
> 공동출원인 구분자(`|`, `;`, `,`)도 실제 파일을 보고 확인해야 합니다.

## 5. 해석 시 주의 (보고서 '한계' 절에 명시 권장)

- **비중(%)과 건수 함께 제시:** 기간별 n이 작으면 1건 차이로 비중이 크게 바뀝니다.
- **최근 구간 과소집계:** P3의 감소는 공개 지연 때문일 수 있습니다. 등록률은 심사 진행 중이라 구조적으로 낮게 나옵니다.
- **lift 해석:** 출현 빈도가 낮은 코드 쌍은 lift가 과대해집니다. count ≥ 2 필터를 거쳤어도 count가 작으면 일화적 근거로 취급하세요.
- **사전 분류:** 키워드 사전은 초안입니다. 시트 08(미분류)과 00(분류결과)을 보고 오분류를 확인한 뒤 `taxonomy.py`를 보완하고 다시 실행하세요. 30건 정도 무작위로 뽑아 수작업으로 대조하면 보고서 신뢰도가 올라갑니다.
- **특허 ≠ R&D 전부:** 보험사는 영업비밀이나 비공개 내부시스템 비중이 높습니다. 특허는 디지털 역량의 하한 지표로만 해석하세요.
- **생태계 해석 자제:** DB손보 특허를 "보험 생태계 동향"으로 일반화하지 마세요. 그러려면 A안 또는 B안이 필요합니다.

# A안: 보험산업 전체 + DB손보 포지셔닝 (`industry.py`)

원 논문 절차를 가능한 한 그대로 구현하고, 기업 비교를 추가했습니다.

| 원 논문 | `industry.py` 구현 |
|---|---|
| 4.2 텍스트 파싱: 명사·명사구 | kiwipiepy 명사(NNG/NNP/SL) + 불용어 |
| log 국소가중 × entropy 전역가중 | `log_entropy()`: log(1+tf) × [1 + Σp·log p / log n] |
| SVD 최대 25차원 | `TruncatedSVD(25)` |
| EM 군집, 최대 20개 | `GaussianMixture`(대각 공분산). k는 BIC 최소로 4~20 범위에서 선택하거나 `--k`로 고정 |
| 대표어: 상위 2m 빈출어를 이항확률 순으로 m개 | `descriptive_terms()`. 군집 안에서 더 흔한 단어로 후보를 한정 |
| 유사 군집 병합(연구자 판단) | `--merge 병합표.csv`. 템플릿은 엑셀 시트 01b |
| 관심분야별 상위 10 IPC, 중분류 수준, 기간별 규칙 | 비중 상위 `--focus`개 군집 × 기간. 원 논문 기준(p.730): **confidence > 60%, lift > 1, 규칙당 IPC 최대 4개**, support 기준 없음. 같은 항목집합의 규칙은 lift가 가장 높은 1개만 남김 |
| (추가) | 기업×군집 RTA, 군집별 최초 진입연도, 기업별 융합 출원 비율, C안 사전 분류 기반 RTA(교차검증), 군집 안정성 ARI |

## 데이터 수집

출원인 OR 검색을 걸고 출원일 2016–2025로 한 번에 내려받습니다. 대상 기업과 출원인 표기는 `FIRMS`에 있습니다.

- 사명 변경 이력(동부화재→DB손보, LIG→KB손보, 대한생명→한화생명, 신한생명·오렌지라이프→신한라이프)은 기억에 근거한 것이므로 **검증이 필요합니다**. 실행 후 시트 11(미매칭 출원인)에서 누락된 표기를 확인해 `FIRMS`에 추가하세요.
- 보험사 계열 IT 자회사(예: 삼성SDS는 그룹 IT사)를 포함할지는 분석 목적에 따라 결정해야 합니다. 기본값은 보험사 법인만입니다.

## 해석 주의

- **RTA는 표본이 작으면 과대·과소 추정됩니다.** 해당 군집 출원이 5건 미만인 기업의 RTA는 보고하지 마세요(시트 05 건수 확인).
- **공동출원은 각 기업에 1건씩 중복 계상합니다**(full counting). 그래서 산업 합계가 고유 출원 수보다 클 수 있습니다.
- **군집은 EM 초기값에 민감합니다.** 요약의 ARI가 0.6 미만이면 `--k`를 줄이거나 병합해 안정화하세요. 0.6은 경험적 기준이며 문헌 근거는 없습니다.
- **연관규칙이 0개로 나올 수 있습니다.** 같은 군집 안의 IPC는 서로 대체 관계(lift ≤ 1)인 경우가 많기 때문입니다. 원 논문도 삼성전자 수만 건에서 여러 구간이 'No rule'이었습니다(Tables IV–VII). 그러면 0개를 그대로 결과로 보고하고, C안의 허브 제외 동시출현 네트워크를 보조로 쓰세요.
- **1회 동시출현 규칙:** 원 논문은 support 기준이 없어 단 1건에서 나온 규칙(confidence 100%)도 통과합니다. 소표본에서 이런 규칙이 많으면 `industry.py`의 `MIN_COUNT`를 2~3으로 올린 결과를 민감도 분석으로 함께 제시하세요.
- **원 논문의 'three consecutive sequential codes' 조건(p.730):** 뜻이 명확하지 않아 구현하지 않았습니다.
- 가상 데이터(`make_dummy_industry.py`)에서는 심어둔 기업별 특화(예: DB손보 = 보상·이미지, 모빌리티)가 병합 후 RTA로 복원되는 것을 확인했습니다. 실제 데이터에서의 성능은 확인하지 못했습니다.

# 실제 데이터 적용 기록 (A안, KIPRIS 2026-10-15 추출, 13개사 258건)

- **군집 설정:** 원 논문 설정(SVD 25차원)에서는 군집 안정성 ARI가 0.2~0.55로 낮았습니다. SVD 8차원과 k=4~12를 비교해 `--svd 8 --k 9`를 택했습니다(ARI 0.90/0.78, BIC 최소 근처). 탐색 결과는 실행 로그에 남겼습니다.
- **불용어 추가:** 특허 문체 상투어("판독 가능", "전술한 과제")와 출원인별 명세서 문체("본 개시", "컴퓨팅 장치")를 추가했습니다. 남겨두면 기술이 아니라 출원인 단위로 군집이 생겼습니다.
- **연관규칙 중복 제거:** 같은 특허 묶음(tidset)이 뒷받침하는 규칙은 같은 융합 패턴으로 보고 항목이 가장 많은 규칙 하나만 남깁니다(원 논문 p.730의 "같은 패턴 규칙 축소" 구현).
- **관심분야:** 비중 상위 2개와 비중 증가 상위 2개로 선정합니다(원 논문 p.728 기준).
- **RTA 그림:** 출원 9건 이상 기업만 표시합니다(`MIN_FIRM_N`). 표에는 전체 기업이 남습니다.
- **원 논문과 다른 점:**
  - 기간별로 따로 군집하지 않고, 전체 기간을 한 번에 군집한 뒤 기간별 비중을 계산합니다. 소표본이라 기간별 군집이 불가능하기 때문입니다.
  - 분석 텍스트로 제목 대신 제목과 요약을 함께 씁니다.
