# KIPRIS 데이터 수집과 점검

## 검색 조건

| 항목 | 설정 | 이유 |
|---|---|---|
| 문헌 종류 | 특허만 | BM 발명은 특허. 실용신안은 물품 형상 대상 |
| 국가 | KR | 해외 출원은 같은 발명 중복 |
| 기간 | **출원일** 기준 | 연구개발 시점에 가장 가까움(원 논문 기준) |
| 법적 상태 | 전부(등록·공개·거절·취하·포기·소멸) | 등록만 받으면 최근 연도가 크게 줄고 등록률 분석 불가 |
| 출원인 | 가능하면 **출원인코드** | 사명 변경·표기 차이에 강함 |
| 생태계 | IPC(예: G06Q 40/08) — 주분류가 아니라 부여된 IPC 중 하나라도 | |
| 분할 수집 | 반기 단위 + 수집 로그(검색건수·수집건수) | 다운로드 상한 대비, 누락 점검 |

KIPRIS 화면·검색식 문법·다운로드 상한은 개편될 수 있으므로 현재 화면 도움말을 따른다.
확장 검색(제목·요약 키워드)은 주변 특허(예: 의료 청구)가 많이 섞이므로 주 분석이 아니라 민감도 분석에 쓴다.

## 필수 열 (`analyze.py`의 `COLUMN_ALIASES`가 자동 매핑)

출원번호, 출원일자, 발명의명칭, 요약, IPC(전체), 출원인(공동출원인 전체), 등록번호, 행정처리상태.
선택: 출원인코드, 문헌종류, CPC(나라 간 비교 시 기준), 대표청구항(등록 회귀 통제변수).
IPC 구분자는 상관없다(정규식으로 코드 추출). 열 이름이 다르면 스크립트가 실제 열 목록을 출력하고 멈춘다.

## 받은 직후 점검

1. 행 수와 고유 출원번호 수 — 공동출원이 회사별 행으로 중복될 수 있다.
2. 연도 분포 — 특정 연도 0건이면 분할 수집 누락 또는 실제 공백. 출원인코드·기간 무제한 재검색으로 확인.
3. 출원인 표기 목록 — 음역·옛 사명·부분일치로 섞인 다른 법인(예: 공익재단) 확인.
4. 법적 상태 분포 — '공개'(심사 중)가 하나도 없으면 최근 출원 누락 의심.
5. 회사별 건수가 보도나 상식과 크게 다르면 검색 누락을 먼저 의심한다(예: 대형사 1–3건).
6. 생태계 파일이면 모든 행에 기준 IPC가 있는지(100%) 확인.

## 다른 데이터

- **USPTO**: CPC 기준. G06Q 40/08은 2025-08에 세부 그룹이 신설되었으므로 상위 그룹으로 합쳐 비교.
  나라 간 비교는 텍스트 군집(언어 차이) 대신 CPC 세부 그룹으로 기술분야를 정의하는 편이 깔끔하다.
- **DART 사업보고서**: IPC가 없어 원 논문 2단계(IPC 연관규칙)는 기술 용어 동시언급으로 바꿔야 한다. 특허와의 삼각검증용.
