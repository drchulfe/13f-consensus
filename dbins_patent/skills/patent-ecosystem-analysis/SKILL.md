# 특허 생태계 기술융합 분석

특허 출원 데이터에서 "어떤 기술분야가 커지고, 무엇이 무엇과 결합하며, 누가 그것을 이끄는가"를 답하는 분석 흐름이다.
Suh & Sohn(2015)의 틀을 출발점으로 하되, 실제 데이터에서 드러난 함정(소표본, 출원인 표기, 명세서 문체, 공개 지연)을
처리하는 규칙을 함께 담았다. 이 규칙들은 한국 보험업 특허(258건, 1,503건)를 분석하며 하나씩 확인한 것이다.

## 0. 먼저 정할 것: 분석 단위와 설계

표본 크기가 설계를 결정한다. 군집과 연관규칙은 표본이 작으면 의미 있는 결과를 내지 못하므로, 시작 전에 건수를 확인한다.

| 설계 | 분석 단위 | 맞는 경우 | 스크립트 |
|---|---|---|---|
| C. 단일기업 사례 | 한 회사 출원 | 수십 건 이하. 통계 대신 **전수 리뷰**(건별 분류표·타임라인) | `analyze.py` |
| A. 산업 비교 | 같은 업종 여러 회사 | 수백 건. 기업×군집 RTA, 동종사 비교 | `industry.py` |
| B. 기술 생태계 | 특정 분류(예: IPC G06Q 40/08) 출원 전체 | 1,000건 이상. 원 논문 설정 그대로 가능, 출원주체 구성·기회 맵 | `ecosystem.py` |

경험칙(문헌 근거 없음, 모형 파라미터 수에서 역산): SVD 25차원·EM 군집을 원 논문대로 쓰려면 대략 1,000건 이상이 필요했고,
258건에서는 SVD 8차원으로 줄여야 군집이 안정했다(ARI 0.78–0.90). 11건짜리 단일기업은 군집·규칙 모두 무의미했다.

## 1. 데이터 준비

`references/data_kipris.md`를 읽고 수집 조건(출원일 기준, 법적 상태 전부, 특허만, 반기 단위 분할 수집)과 필수 열을 맞춘다.
받은 파일은 바로 분석하지 말고 먼저 프로파일링한다: 건수, 연도 분포, 출원인 표기 목록, 법적 상태, IPC 형식.
이 단계에서 잡힌 문제가 가장 많았다. 예를 들어 KIPRIS는 출원인을 **현재 사명의 한글 음역**으로 표시한다
("DB손해보험"이 아니라 "디비손해보험 주식회사"). 출원인 사전(`industry.py`의 `FIRMS`)을 실제 표기에 맞춰 고친다.

## 2. 실행

모든 스크립트는 `scripts/`에 있고, 서로 import하므로 같은 폴더에서 실행한다. 파이썬 패키지:
`pandas openpyxl scikit-learn scipy networkx matplotlib koreanize-matplotlib kiwipiepy tabulate statsmodels`.

```bash
# C. 단일기업
python scripts/analyze.py <파일.xlsx> --asof <추출일> --out out_c
# A. 산업 비교 (소표본이면 --svd 8, k는 안정성 탐색 후 고정)
python scripts/industry.py <파일.xlsx> --asof <추출일> --out out_a --svd 8 --k 9
# B. 생태계 (1,000건 이상이면 원 논문 설정)
python scripts/ecosystem.py <파일.xlsx> --asof <추출일> --out out_b --svd 25 --k 12 --actors actors.csv [--merge merge.csv] [--broad]
# 검증·강건성: 선도기업 대리변수, 등록 회귀, 규칙 유의성
python scripts/robustness.py <파일.xlsx> out_b/ecosystem_tables.xlsx actors.csv --out out_p1 --draws 300
# 출원인 전수 유형 분류 초안 (사람 2명이 확정 → κ)
python scripts/actor_draft.py <파일.xlsx> actors.csv actor_draft.xlsx
```

회사·업종을 바꿀 때 고칠 곳: `industry.py`의 `FIRMS`(표준 회사명 → 출원인 표기 목록)와 `FOCAL`,
`ecosystem.py`의 `CORE_IPC`·`ACTOR_RULES`, `robustness.py`의 `LEADERS`, `analyze.py`의 `FOCAL_NAMES`, `taxonomy.py`의 사전.

처음 쓰는 환경이면 `make_dummy*.py`로 가상 데이터를 만들어 파이프라인이 끝까지 도는지 먼저 확인한다
(가상 데이터 결과는 절대 해석하지 않는다).

## 3. 군집 설정 정하기

k를 BIC 최소로만 고르면 상한(20)에 붙어 과분할되기 쉽다. SVD 차원 × k 격자에서 BIC와 초기값 간 ARI를 함께 보고,
**ARI ≥ 0.7 근처이면서 BIC가 꺾이는 지점**을 고른다. 군집이 한 회사 출원으로 채워지면(예: 82%가 한 회사)
명세서 문체 때문일 수 있으니 대표어를 확인하고 불용어(`industry.py`의 `STOP`)를 보강해 다시 돌린다.
"본 개시", "컴퓨팅 장치", "판독 가능", "전술한 과제" 같은 표현이 대표어로 올라오면 그 신호다.

## 4. 원 논문 기준과 다르게 한 것은 모두 밝힌다

`references/suh_sohn_2015.md`에 원 논문 설정(쪽수 포함)과 이 스킬의 차이가 정리되어 있다. 논문·보고서에는 차이를 표로 적는다.
연관규칙은 원 논문 기준(confidence > 60%, lift > 1, 규칙당 IPC ≤ 4, support 기준 없음)을 기본으로 하되,
같은 특허 묶음이 뒷받침하는 규칙은 하나로 합친다(원 논문 p.730 "같은 패턴 축소"). support 기준이 없어 1건짜리 규칙이
많이 나오므로 초기하분포 검정 + BH 보정 결과를 함께 보고, 서술은 q < .05 규칙 중심으로 한다.

## 5. 검증 (논문으로 갈 때)

`references/validation.md`에 설계와 해석 기준이 있다. 핵심은 세 가지다.
- **선도기업 대리변수 검증**: 선도기업의 군집 구성이 '같은 규모의 무작위 출원인 묶음'보다 생태계와 덜 닮았는지 순열검정.
  무작위 특허가 아니라 무작위 출원인으로 묶어야 질문("다른 기업 집단보다 대표성이 낮은가")에 맞다.
- **등록 로지스틱 회귀**: 심사가 끝났을 기간(공개 지연 고려)만, 연도·군집 고정효과, IPC 수·청구항 길이 통제.
- **강건성 격자**: k × 초기값 × 선도기업 정의. 결과는 중앙값과 'p < .05 비율'로 보고한다.

## 6. 함정 목록

`references/pitfalls.md`를 분석 전에 한 번 읽는다. 실제로 결과를 틀리게 만들었던 것들이다
(출원인 쉼표 분리 버그, 사명 변경 미반영, 같은 날 같은 제목 출원의 중복 집계, 18개월 공개 지연, 사전 분류의 오분류 등).

## 7. 보고 원칙

- 수치마다 건수를 함께 쓴다. 비중(%)만 쓰면 1–2건 차이가 추세처럼 보인다.
- 사실(데이터에서 계산)과 추정(해석)을 구분해 표시한다. 군집 이름, 출원인 유형, 업무영역 분류는 분석자 판단이므로 추정이다.
- RTA는 출원이 적은 기업에서 극단값이 되므로 그림에는 일정 건수 이상 기업만 넣는다(기본 9건).
- 보고서의 숫자는 분석 결과 파일에서 스크립트로 채운다. 손으로 옮기면 틀린다.
